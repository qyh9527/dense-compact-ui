# 通用前端工作流与自动验收研究

研究日期：2026-10-06。本文面向维护者，说明本 PR 的判断、实现边界与验证证据。它不属于技能运行指令，也不通过 SKILL.md 加载；`.gitattributes` 将 docs 排除在发布包外。

## 结论

现有项目已经有明确的空间语言：密度档位、行模型、空间预算、连续分区、圆角角色与专题规则。新增价值在于把任务上下文、修改边界和验收证据组织成可执行流程，并将一部分可判断的问题交给确定性工具。

项目定位是通用前端的紧凑设计与评审。Web、桌面、原生和跨平台共享任务判断与设计原则；角色获取、尺寸单位、可见性、命中区域和无障碍验证由平台适配器负责。首版工具覆盖有限平台，不等于技能只服务这些平台。

## 合并前的收窄

评审后本 PR 只合并工作流文档，下文「自动检测的取舍」「工具边界」和测试证据描述的检测器、Web 快照脚本与 Claude Code Hook 从本 PR 移出，不进入 main，按后续研究重新设计后再单独提 PR。原因：六条规则都要求产品源码先加 `data-dc-role` 标注才有覆盖；Web 快照没有在真实浏览器运行过；Hook 没有在真实会话验证；解析依赖与 CI 给技能仓库增加了长期维护面。

同时补上三处保护视觉质量的规则：quality-workflow.md 的复验在停止前加一次观感检查；影响辨认或操作的视觉问题按 P2 定级；精简时保留签名元素（1px 分隔线分区、圆角角色、`tabular-nums`、强调色配额）。原 sources.md 里的主依据与取舍说明移到 [design-rationale.md](design-rationale.md)，运行规则仍不出现其他 Skill 名称。

## 研究对象与资料

研究过程对照了 [Impeccable 的技能与工作流](https://github.com/pbakaus/impeccable/tree/489855d98d4502bc2f46af77d4de37e7ef650e10/skill) 和 [writing-for-agents](https://github.com/mattpocock/skills/blob/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d/skills/productivity/writing-for-agents/SKILL.md)。这些名称与比较只出现在维护研究中，不进入技能入口、参考规则或操作示例。未复制上游提示词、脚本或检测器。

技术实现核对了 [Claude Code Hook 协议](https://code.claude.com/docs/en/hooks)、[Babel parser](https://babeljs.io/docs/babel-parser)、[parse5](https://parse5.js.org/)、[Web 计算样式](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle) 和 [WCAG 目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。44px 是本项目的 Web 触屏设计目标，不能将一次小于 44px 的边界量取直接写成 WCAG AA 违规。

## 本次设计决策

| 决策 | 原因 | 落地 |
| --- | --- | --- |
| 产品事实与视觉约定分层 | 更换风格不能改写用户任务；从代码观察到的外观不能反推受众身份 | 当前要求 → 已有产品文档 → DESIGN / 页面约定 → 组件与 token → 空间预算 |
| 页面模式属于页面或区域 | 同一产品可能同时有工作台、帮助正文和宣传页 | operate / read / persuade / experience；模式不替代用户风格授权 |
| 集中检查、批量修正、确认后停止 | 重复截图和细节微调容易脱离完成条件 | 首次覆盖适用设备与状态，第二次聚焦修复处；必要缺陷继续处理 |
| 确定性规则与平台适配器分开 | 同一个字号数值在 CSS px、pt、dp、sp 中不能直接比较 | 源码 AST 适配器、Web 快照适配器与共享语义检查 |
| Hook 可选且项目启用 | 安装技能不等于授权修改宿主配置或强制换风格 | 显式安装，配置开关，只读检查，不自动改源码 |
| 研究记录独立存放 | 运行规则应直接说明如何工作，避免维护历史和跨技能依赖 | 删除技能内其他 Skill 的名称、对比与“吸收来源”叙述；设计依据与取舍移到 [design-rationale.md](design-rationale.md)；sources.md 保留标准、平台指南和规则出处 |

## 自动检测的取舍

| 候选规则 | 首版状态 | 理由 |
| --- | --- | --- |
| DC001 正文字号 | 已实现：显式正文角色，源码字面值 / Web 计算样式 | 不把次要文本、动态样式或原生单位当成 13px 违规 |
| DC002 行高偏差 | 人工任务评审 | 缩放、展开、热区与字体都会合理抬高行高 |
| DC003 卡片嵌套 | 已实现：显式卡片角色，浮层为边界 | 不从组件名或 class 猜对象关系 |
| DC004 邻接圆角 | 人工任务评审 | 需要几何、共边关系及角色判断 |
| DC005 数字排布 | 已实现：Web 计算样式 | 未声明 tabular-nums 是核对线索，实际字体可能已有等宽数字 |
| DC006 卡片过多 | 人工任务评审 | 元素数量不能证明卡片是否承担必要功能 |
| DC007 强调色面积 | 人工量取与评审 | CSS 中颜色出现次数不是渲染后的面积比例 |
| DC008 触屏边界 | 已实现：Web 交互元素边界量取 | 标签、伪元素、实际命中与 WCAG 例外仍需验证 |
| DC009 表格换行 | 人工任务评审 | 是否换行取决于字段语义与比较任务 |
| DC010 敏感内容省略 | 已实现：金额 / 计数 / 错误角色 | 源码给疑点；Web 快照要求实际横向裁切 |
| DC011 条带密度 | 人工任务评审 | 不能将实际高度偏差等同于最小高度档位不一致 |
| DC012 多个主操作 | 已实现：显式视图和主操作 | 源码分支可能互斥；渲染快照只统计可见可用项 |

显式语义标记是首版的保守选择：数据可重复判断，未知语义保留未知。它牺牲部分自动发现范围，换取较低误报风险；报告必须同时显示覆盖和错误，零告警不能作为合格证明。

## 工具边界

- 源码：HTML / Web JSX / TSX 使用完整 AST。动态表达式、样式展开、外部 CSS 级联、跨文件组件展开不推断；其他栈明确列为未支持。
- Web：采集当前页面的角色、计算样式和几何，不收集正文、不联网。结果不能证明点击、读屏、软键盘或物理触控通过。
- 宿主：当前仅实现 Claude Code PostToolUse，使用 command + args 避免路径经 shell 重解释。其他 Agent 可运行同一 CLI，但未宣称其原生 Hook 已适配。
- 配置：项目内启用，安装合并设置，重复安装幂等，卸载只移除本安装路径的处理器。未知或无效设置拒绝写入。
- 范围：Hook 只读受影响文件，Bash 后读 Git 工作树候选，不执行事件里的命令、不读 transcript。候选与反馈有上限，完整检查由 CLI 承担。

## 验证证据

`npm test`：16 项测试全部通过，包含以下行为：

- HTML / TSX 结构解析、字面字号、动态样式与 spread 保持未知、隐藏祖先传播、独立视图同名隔离、局部例外理由。
- 六类规则的命中与反例；Web 与原生单位隔离；触屏开关、可见性、裁切状态、禁用操作；行高变化不自动判违规。
- CLI 退出码、解析错误、未支持文件、符号链接与项目边界。
- Hook 显式启用、输入错误、无 HEAD Git 仓库、仓库内子项目、已暂存与未跟踪候选；安装、重复安装、卸载和无效配置保留。

独立代码审查复现的路径和误报问题已修复，定向复验通过。独立技能试用在 Flutter 桌面监控场景中给出逻辑单位空间预算、操作区与阅读区分工、小窗口 / 字体缩放 / DPI 和平台无障碍计划，没有将浏览器设为前提，也未把规格宣称为实测通过。

技能格式、本地文档链接、差异格式与发布包隔离检查另行执行。研究文件不会出现在发布包，运行规则没有其他 Skill 引用。

限制：本环境缺少可运行的 Chromium，尝试下载后仍未取得有效运行文件，因此未完成真实 Web 页面测量；Web 捕获脚本仅做语法与定向逻辑检查。没有在真实 Claude Code 会话、Windows/macOS、原生模拟器或真机执行端到端验证。相关输出不宣称这些检查通过。

## 后续扩展条件

新增平台适配器时，先提交真实样例，明确角色、单位、可见性与命中区域映射，再复用共享规则；不要求原生组件添加 HTML data 属性。新增自动规则时先证明有足够信息作出判断，再加入误报样例和失败反馈；不以扩大规则数量作为目标。
