# 登录、注册与验证

做登录、注册、找回 / 重置密码、二次验证、通行密钥、会话过期重新登录时读。这些是聚焦型任务：用标准尺寸（comfortable 档或项目常规尺寸），不压密度；配色沿用主题。

## 表单结构

- 每个流程一个独立的 `<form>`（登录、注册、找回分开），带提交按钮；输入框有 `<label>`，`name` / `id` 稳定，不随部署变化。
- `autocomplete` 取值：

| 字段 | 写法 |
| --- | --- |
| 账号（邮箱 / 手机号 / 用户名） | `autocomplete="username"`；邮箱加 `type="email"`，手机号加 `type="tel"` |
| 登录密码 | `type="password" autocomplete="current-password"` |
| 注册、改密的新密码 | `autocomplete="new-password"` |
| 短信 / 邮件验证码 | `autocomplete="one-time-code" inputmode="numeric"` |
| 支持通行密钥的账号框 | `autocomplete="username webauthn"` |

- 先输账号、再输密码的分步流程：密码页带一个隐藏的账号字段（值为上一步输入的账号），密码管理器才能对上。
- 不要求重复输入邮箱或密码；用「显示密码」代替确认框。

## 无障碍（WCAG 2.2 · 3.3.8）

- 不阻止粘贴，不关闭自动填充；不把密码或验证码拆成多个单字符框，除非整段粘贴能一次填满。
- 提供「显示密码」切换：有可访问名称、标明当前状态，并提示会明文显示。
- 不把要求辨认文字或解题的图形验证码作为唯一路径。
- 至少提供一种不靠记忆的方式：通行密钥、邮件登录链接、第三方登录之一。
- 密码要求写在输入框下方，用 `aria-describedby` 关联，输入时实时显示是否满足。

## 密码规则（NIST SP 800-63B）

- 不强制大小写、数字、符号的组合；不定期强制改密，只在疑似泄露时要求修改。
- 长度：单独用密码时至少 15 位，配合多因素时至少 8 位；允许至少 64 位，允许空格和所有可打印字符。
- 拒绝常见和已泄露的密码，并说明原因。

## 错误与安全提示

- 登录失败统一说「账号或密码不正确」，不区分账号不存在、密码错误、账号停用。
- 找回密码统一说「如果该邮箱已注册，我们会发送重置邮件」；注册时账号已存在也用中性说法，并给出登录或找回入口。
- 限流或锁定时说明能做什么、多久后可以重试，不暴露账号是否存在。
- 提交时按钮进入进行中状态并防止重复提交；失败后保留已输入的账号。
- 会话过期：先保留当前页面和未提交内容，重新登录后回到原处。

## 通行密钥

- 已有密码用户：登录页加载时发起条件式 WebAuthn 请求（`mediation: 'conditional'`），聚焦账号框时，通行密钥和已存密码一起出现在自动填充里。
- 密码登录成功后，提示创建通行密钥（或用条件式创建自动生成）；忘记密码时可以直接引导创建通行密钥。
- 用通行密钥登录后不再追加第二因素。

## 布局

- 单列，宽约 360–420px；只有一个主按钮（「登录」），第三方登录和注册入口用次要样式。
- 「忘记密码」放在密码框附近；验证码页写明发送到哪里（部分打码），并显示重发倒计时。
- 移动端软键盘弹出时，提交按钮仍可见；验证码支持系统自动填充。

## 检查

- 浏览器和密码管理器能自动填充并保存账号密码；能粘贴密码和验证码。
- 错误提示不区分账号是否存在。
- 键盘能完成全流程，焦点顺序正确，错误能被读屏读到。
