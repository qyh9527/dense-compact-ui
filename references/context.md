# 页面任务、产品事实与平台验证

核心流程不依赖容器：先确定任务和平台，再选空间体系与验证手段。Web、桌面、原生、跨平台界面都沿用这一顺序。

## 上下文读取

1. 当前用户要求与已确认约定。
2. 已有产品文档（如 PRODUCT.md）：受众、核心任务、环境、数据与业务约束；从代码观察到的现状只算观察，不当成用户确认的事实。
3. DESIGN.md 与页面覆盖：当前主题、密度、字阶、形状、布局、组件和交互约定。
4. 实际组件与 token：核对实现、平台、单位和依赖，再为当前页面制定空间预算。

产品事实回答「谁要完成什么任务」，视觉约定回答「界面怎样表达」。换主题或密度不改写产品事实。项目已有文档用原路径；没有文档时利用当前请求和现有实现，只有缺失信息会改变方向才问一个问题。局部修改不强制创建或重写文档。

## 按页面判模式

| 模式 | 成功意味着 | 本技能的默认范围 |
| --- | --- | --- |
| operate 操作 | 完成操作、比较、编辑或监控 | 推荐完整空间体系，沿用用户的风格选择 |
| read 阅读 | 理解正文、说明或知识 | 只借用字体、阅读层级、响应式和可达性检查 |
| persuade 说服 | 做出购买、报名等决定 | 默认不启用紧凑视觉体系，明确要求时才选用 |
| experience 体验 | 浏览作品或沉浸于内容 | 默认不启用紧凑视觉体系，按需借用基础交互检查 |

模式属于当前页面或区域，不属于整个产品。管理工具的宣传页是 persuade，帮助正文是 read；编辑器主区与帮助侧栏可以采用不同阅读节奏。operate 不等于所有控件都缩小：登录、引导、长表单、结账和破坏性确认保持标准尺寸。明确的用户选择优先，模式不自动替用户授权换风格。

## 验证适配器

| 平台 | 量取与操作证据 | 注意 |
| --- | --- | --- |
| Web | 浏览器计算样式、布局量取、键盘与触屏操作、截图 | CSS px；窄屏截图不等于触屏手势和软键盘通过 |
| 桌面 | 实际窗口、平台无障碍树、键盘路径与 UI 测试 | 小窗口、DPI、系统字体缩放；WebView 内外分别验证 |
| 原生 | 模拟器 / 真机、布局检查器、平台 UI 测试和无障碍工具 | iOS 用 pt、Android 用 dp / sp；按平台热区标准 |
| 跨平台 | 框架测试与各目标平台实际渲染 | 共享代码不证明不同平台的字体、热区和返回行为一致 |

现有测试和工具可直接复用。无法运行时只做静态检查，列出待验证项；不因没有浏览器而阻塞源码工作，也不把浏览器作为原生项目的验收前提。不同单位不能直接套用 Web 的 13px / 24px / 44px 数值。

## 有限轮次的视觉检查

首次检查一次采集适用的窗口 / 设备、长内容、文字缩放和任务状态；按影响集中修复。第二次只确认修改处和共享组件受影响处。通过后停止样式微调；存在明确功能或可达性缺陷时继续针对该缺陷修复并记录原因。此流程限制重复美化，不限制必要修复，也不让未验证项自动变成通过。
