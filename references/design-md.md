# 一页 DESIGN.md

给已有项目整理设计系统时用。目标：新会话或新成员只读这一页，就能写出风格一致的界面。

## 怎么写

1. 从代码反推，不凭印象：读全局样式、Tailwind / UnoCSS 配置、CSS 变量、组件库主题、共享布局组件。
2. 第一行写来源文件，方便日后核对是否过期。
3. 每条写**规则 + token 名 + 具体值**；token 名与代码一致，旧名字和实际含义不符时注明（如「token 名是 legacy 的 blue，实际品牌色是绿」）。
4. 只写这个项目的取舍，不抄通用常识。一页以内，约 30–60 行。
5. 写完对照代码抽查 3 处，确认值没抄错。

## 模板

```md
# <项目名> — Design System

来源：`<样式文件>` + `<配置文件>`。工具类使用 `<前缀>-*` token。

## 色彩
- 中性色：`<token 范围>`，<是否带色相、色相值>；默认 <深/浅> 色。
- 强调色：`<token>` = `<值>`，只用于 <主操作 / 当前选择 / 关键数字>；面积 ≤10%。
- 语义色：success `<值>`、warning `<值>`、error `<值>`、info `<值>`。
- 黑白基准：`<近黑值>` / `<近白值>`，不用纯 #000/#fff。
- 图表分类色：来自 `<函数或 token，默认 --dc-viz-*>`，只在图表内使用。

## 字体
- 无衬线：`<字体栈>`（`<类名>`），一族承担全部文字。
- 等宽：`<字体栈>`，用于 <计数 / ID / 终端文本>。
- 数字 `tabular-nums`；固定字阶 `<范围>`，不用流体标题；例外：<大号指标及其限宽方式>。

## 布局与组件
- 卡片：`<组件>`（<边框 + 阴影规则>），不嵌套。
- 圆角：<控件 / 容器 / 胶囊 的 token 与值>。
- 外壳：宽屏 <侧栏写法>，窄屏 <顶栏 + 抽屉写法>；内容在 `<滚动容器>` 内滚动。
- 断点：<sm/md/lg 值>；手机目标 <宽度范围>。
- 动效：<库>，<缓动>，<时长>，只传达状态；尊重 `prefers-reduced-motion`。

## 移动端规则
- Tab / 分段：单行横滑，不换行。
- 大号指标：<字号限制方式>，360px 不裁切。
- 表格：<断点> 以下收起次要列，核心指标在屏内；细节进 <展开视图>。
- 触屏热区 ≥<值>px；按压反馈用 `active:`。
```

占位符全部替换成项目实际值；某节在项目里不存在就删掉，不留空模板。

## 主文件与页面覆盖

页面之间差异大时（如列表页紧凑、结账页保持标准尺寸），例外不塞进主文件：

- `DESIGN.md`：全局规则，唯一权威来源。
- `design/pages/<页面名>.md`：只写这一页和主文件不同的地方，开头注明覆盖了哪几条。
- 做某个页面时先读 DESIGN.md，再看有没有对应的页面文件；有就以页面文件为准，没有就只用主文件。
- 已有 DESIGN.md 时先读再改，不整份重写，避免覆盖别人已定的决定。
