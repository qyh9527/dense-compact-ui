## 参考图

参考图只提炼空间关系：距离、对齐、邻接、面积分配，以及重复对象的行模型（单行还是多行、哪些列常驻、操作放在哪）。业务名称、区域数量、控件清单都从当前产品需求来；「主内容」「关联区域」这类分析用词不写进界面文案。

## 有效密度

密度 = 可见区域里对当前任务有用的信息与操作，不是元素个数。按这个顺序找空间：

1. 删重复包装：一层边框能说清的，不套第二层。
2. 删重复文案：上下文已经说明的标签、说明、单位不再写。
3. 删无用距离：没有分组、阅读或防误触作用的留白。
4. 最后才缩组件尺寸。

空间先给核心内容、必要操作和关键状态；导航、辅助说明、装饰按实际使用分配。留白有分组、阅读或防误触作用时保留。

## 距离与层级

- 近 = 关系强，远 = 职责变化；同一种关系全界面用同一个间距。
- 同类元素共享基线、列宽、行高和控件尺寸。
- 层级用字重、位置、细边界、少量表面明度差表达。容器只为真实结构添加，**不嵌套卡片**：卡片内需要再分组时用细分隔线或对齐行。
- 局部状态和局部操作贴着对象放。
- 同类区域用同一套结构，差异靠内容、角色和状态体现。

## 密度配套

- **密组件配松分组。** 组件越紧凑，分组间距和页面外边距越要拉开；密组件加密网格会让分组糊成一片。
- **同一视图的高度配套。** 表头与数据行同高；工具栏、批量操作条与行高同档。档位跟 `tokens.css` 的 `data-density` 走：dense（默认，行 24px / 控件 22px / 正文 13px）/ compact（行 32px / 控件 28px / 正文 14px）/ comfortable（行 40px / 控件 36px / 正文 16px）。
- **同档指最小高度。** 条带、行、控件用 `min-height` / `min-block-size` 取档位值，不写固定 `height`；文字靠内边距或弹性居中，不用「`height` 加等高 `line-height`」的写法。这样 200% 文字缩放、系统大字号时条带自己撑高，不裁切也不叠字。表格单元格的 `height` 本身按最小高度算，可以照写。
- **控件高是视觉高度。** 22px 指控件的视觉表面；控件实际最小高度取 `max(var(--dc-control-height), var(--dc-hit-size))`，可点的行同理取 `max(var(--dc-row-height), var(--dc-hit-size))`。只写控件高会得到低于热区下限的控件。
- **高密档不用通用卡片。** dense 档的区域不再包「边框 + 圆角 + 内边距」的卡片，改为贴边分区：区域之间 1px 分隔线，区块标题做成与行同高的标题条，指标排成一条用竖线分隔的指标条。卡片只留给需要视觉辨识的独立对象（缩略图、可拖动的块）和浮层。compact 档可用轻量卡片，comfortable 档照常。
- **整体切档。** 切密度时同一视图的组件一起切，不单独压某一个组件。
- **密度是用户设置。** 默认档位由产品决定，之后由用户切换，不随断点或方向自动变化；切换入口本身用标准热区。触屏只改热区和正文：`tokens.css` 在主指针为触屏（`pointer: coarse`）时把 `--dc-hit-size` 提到 44px、正文提到 1rem，行高仍随档位，可点的行和控件经上面的 `max()` 到 44px，只读行和间距照常随密度切换。不用 `any-pointer`，否则带触屏的电脑用鼠标时也会被放大。
- **聚焦型任务不压密度**：菜单选择、逐项填写的长表单、引导、结账、破坏性确认。

| 走偏 | 改成 |
| --- | --- |
| 表格行 24px，表头 40px，工具栏 48px | 三者同档：行 24px、表头 24px、工具栏 24px |
| 行距压到 2px，区块之间也只隔 4px | 行内保持紧凑，区块之间拉到 12–16px |
| 高密档每个区域都包一层卡片 | 贴边分区 + 1px 分隔线 + 行高标题条；KPI 改为横排指标条 |

## 承载结构

| 信息形态 | 优先用 | 要保住的 |
| --- | --- | --- |
| 重复且可比较 | 行、列表、表格、树 | 对齐、扫描、对象关系 |
| 连续阅读或输入 | 连续内容区 | 可读行宽与行距 |
| 成组属性 | 对齐字段组、紧凑网格 | 标签关系、输入顺序 |
| 空间位置有意义 | 画布、专门的空间视图 | 位置、尺度、直接操作 |
| 需视觉辨识的独立对象 | 轻量卡片、缩略网格（高密档只用于这类对象） | 辨识度、局部操作 |

紧凑卡片靠共享网格、适度内边距和轻量边界取得密度。

## 行模型

做列表、表格、树时先分清四个概念，判读和空间预算里按这些词写：

| 概念 | 含义 | 由什么决定 |
| --- | --- | --- |
| 一页显示全部 | 全部项在同一个连续列表里，允许滚动 | 用户要连续浏览、逐项比较或全量核对 |
| 一屏显示全部 | 不滚动就能看完 | 项数少，且任务要求同时看到全部 |
| 单行折叠态 | 每项默认一行，列横排 | 重复对象的默认形态 |
| 展开详情 | 点开后在原位或详情区看到更多 | 描述、完整名称、路径、来源、原始数据、完整错误 |

- 折叠态只放扫览和比较必需的列：身份、关键状态、高频操作，其余进展开详情。每列写清宽度和截断方式（见 patterns.md 的「长内容」）。
- 默认字段确实需要两行时（如邮件的主题 + 摘要）写明理由，按两行算行高预算；错误这类必须注意到的状态在折叠态用标记提示，全文放展开详情。
- 实际行高按预算对照：同一视口里可辨认的项数是否达到任务需要，和改版前相比是否更多。设备含触屏时另算一份：可点的行按 44px 计。
- 内容区宽度跟着承载结构走：连续阅读和表单限宽（见 chat.md、settings.md），总览型列表和表格按列宽铺开，宽屏空间先分给列；放不下时的处理见 tables.md 的「结构与列宽」。

## 控件

- 同阶段、同作用域的操作组成工具组：单行、同高、同基线。每个视图最多一个高亮主按钮。
- 高频直接可达，次要按需展开，低频进具名入口（「更多」「设置」）。
- 固定工具区的高度计入空间预算，主体面积留给内容。
- 搜索框、路径输入等承担定位或输入的控件给弹性宽度，并设合适的最小宽度。
- 空间不够时依次：短标签 → 熟悉图标（有可访问名称，触屏也能看懂）→ 重新分组 → 低频项收纳 → 有语义的换行。**Tab / 分段控件例外：不换行，改单行横滑**（见 responsive.md）。

## 字体与数字

- 一个无衬线族（优先系统字体栈）承担全部文字；层级靠字重和字阶，不靠换字体。
- 等宽字体只用于 ID、哈希、路径、token 数、终端风格文本。
- 会上下对比或实时变化的数字（计数、金额、百分比、时间）加 `font-variant-numeric: tabular-nums`，避免列不齐和跳动。
- 产品界面用固定字阶，不用 `clamp()` 流体标题。唯一的大号指标（如总花费）可以例外：用 `clamp()` 或断点控制字号，并限制宽度，保证 360px 下不裁切、不换行断数字。
- 不把极小字号当密度手段；辅助文字可以小一档，正文、关键状态和输入内容保持可读。
- 不用负字距（`letter-spacing` 小于 0）挤空间；中文和正文保持默认字距，只有大号标题可以微收。

## 渐进展示与文案

第一层只放：对象身份、必要信息、关键状态、高频操作。详细内容、高级配置、原始数据逐层展开，展开方式（局部展开 / 详情区 / 浮层）以保留当前对象和上下文为准。

- 标签短，利用已有上下文。
- 状态、类型、数量用小型内联标记；完整说明放在需要它的位置。
- 空状态：一句原因 + 当前任务的下一步，容器保持可用。
- 浮层和模态沿用同一密度语言，可以为阅读稍放宽间距。阴影只表达真实抬升；常规区域靠边界和表面分层。

## 起始标尺

可调起点，依字体、内容、设备和空间调整。密度 token 与主题 token 分开维护。

| 尺度 | 起点 | 用于 |
| --- | --- | --- |
| 行内间距 | 2–4px | 同一信息或操作内部 |
| 同组间距 | 4–6px | 同职责的相关元素 |
| 区域内边距 | 6–8px | 紧凑内容与工具组 |
| 独立组间距 | 8–12px | 职责变化 |
| 桌面视觉控件高 | 22–32px | 工具组 |
| 桌面单行重复内容高 | 24–32px | 列表、表格行 |
| 正文 | 13–16px | 用相对单位，保留用户缩放 |
| 区域标题 | 14–18px | 配合字重与位置 |
| 图标视觉尺寸 | 14–18px | 与实际热区分开算 |
| 状态过渡 | 80–180ms | 只传达状态变化，尊重减少动效偏好 |

圆角尺度见 shape-radius.md，热区与对比度要求见 verify.md。
