# 审计、评审与定向改进

根据请求选一条路径，只读该路径需要的专题。先完成 SKILL.md 的风格选择；「只借用检查」时以项目现有设计系统为准，不套用本技能的主题或密度默认值。

## 选路径

| 请求 | 做什么 | 完成条件 |
| --- | --- | --- |
| 审计、audit、查问题 | 对照 verify.md 检查可达性、状态、布局、主题与性能；只报告，不改文件 | 每项发现有位置、证据、影响和复验方法；未覆盖项注明 |
| 设计评审、critique、为什么不好用 | 沿主要任务检查信息层级、查找与比较、操作距离、上下文保持；只报告，不改文件 | 区分可证实的缺陷与设计建议，说明对当前任务的影响 |
| 打磨、polish、统一细节 | 修正范围内的对齐、token 漂移、状态与文案不一致 | 主要任务复验通过，既定品牌、信息架构和行为保持一致 |
| 精简、distill、去模板味 | 删重复包装与信息，合并重复说明；按操作频率安排入口 | 必需字段、批量比较和常用操作仍可达，空间收益有对照 |
| 加固、harden、边界情况 | 按目标设备补长内容、空值、失败恢复、权限与网络异常 | 失败后输入、选择和恢复入口可用；未验证的状态明确列出 |

「评审并修复」授权先报告发现再实施，不必再次询问；仅要求评审时停在报告。局部请求只处理指定区域，只有共享组件确为根因时才扩大修改，并检查受影响的使用处。

## 建立基线

1. **限定目标。** 记录页面 / 组件、主要任务、设备、当前状态、可改范围及已有设计约定。优先用当前请求、DESIGN.md、已有 PRODUCT.md 和项目文档；区分已确认事实与推断。缺少文档本身不阻塞局部改进。
2. **选代表性内容。** 使用同一组字段、记录、筛选和选中状态做前后比较。涉及已有项目时先读 redesign.md；密度数值与测量口径沿用 layout-density.md、verify.md，不另建评分尺。
3. **检查真实路径。** 从进入页面到完成主要操作，覆盖任务相关的加载、空、成功和失败状态。桌面工作台重点走比较 / 批量操作与键盘路径；手机任务重点走触屏、软键盘与返回恢复。未执行的路径不能写成测试通过。

## 写可执行的发现

每条发现使用：`优先级｜位置｜证据与验证方式｜用户影响｜最小改法｜复验方法`。同一根因合并，列出受影响区域；把样式偏好单列为建议。

| 优先级 | 判断依据 |
| --- | --- |
| P0 阻断 | 核心任务无法完成、工作内容丢失或结果状态误导 |
| P1 严重 | 主要操作明显受阻、关键内容不可读或可达性要求不满足 |
| P2 一般 | 存在绕行方式，但增加查找、操作或理解成本 |
| P3 打磨 | 不影响完成任务的局部一致性问题 |

先按真实影响定优先级，同级再按 SKILL.md 的领域顺序排。没有运行性能测量时只报告可核对的风险；没有截图或运行界面时只做静态结论。不把检测告警数量或主观总分当成可用性证明，也不凭有限检查宣称全面符合无障碍标准。

## 定向修改

- **打磨：找最小责任层。** 局部偏差改局部；重复偏差查共享组件；已有 token 能表达时直接复用，只有实际复用需求才新增 token。缺少 DESIGN.md 时先沿用一致的现有实现，不把项目判成空白画布。
- **精简：先减噪声。** 去掉重复边框、容器和说明，再考虑折叠低频内容。为每个移走的字段或操作说明去向；表格的比较列、状态和高频操作优先常驻。不得为减少元素数量破坏一屏总览或把所有行内操作藏进菜单。
- **加固：按失败路径补齐。** 只检查产品支持的设备与语言；关注加载后无数据、超时重试、权限不足、重复提交和部分失败。让用户知道哪些成功、哪些失败，保留尚未完成的输入与选择。触屏热区与控件视觉尺寸分别检查。
- **文案：说清动作和恢复。** 按钮写出动作与对象，错误提示给出可执行的下一步；沿用产品术语。保留事实性声明、法律文案和业务含义，既有受保护约定按 redesign.md 处理。

## 复验与停止

1. 改前记录基线，集中修复本次范围内的发现；按 verify.md 用同一内容、视口、主题和状态复验，说明任务相关的检查覆盖。
2. 有预览条件时，先集中检查适用设备与状态，再批量修正，最后做一次确认；已达标后停止美化。有明确未解决缺陷时继续针对该缺陷处理，不以轮数代替完成条件。
3. 交付时逐项标「已修复 / 未解决 / 建议」及「预览验证 / 静态检查 / 未验证」。有浏览器检查时附截图或量取记录；静态改动不能证明触屏、焦点或视觉效果已通过。

只有已授权范围完成、关键发现已复验或如实列明限制，才结束本轮。遇到新方向建议单独列出，不自动扩成整页重做。
