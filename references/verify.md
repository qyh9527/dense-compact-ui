# 交付前检查

用当前产品的代表性内容检查，不用占位符。交付时把结果贴在回复里，每项标「预览验证 / 静态检查 / 未验证」，不适用的项写明原因后跳过。

## 边界场景

按判读里的设备取舍：标「手机」的项只在设备含手机时检查，标「桌面」的项只在设备含桌面时检查，触屏热区只在设备含触屏时检查；跳过的项写明原因。

- [ ] 长标题、长标签、长数字（金额、ID）不撑破布局
- [ ] 200% 文字缩放后仍可读、可操作
- [ ] 手机：宽度窄到 360px 时 Tab 单行横滑，表格核心列在屏内，大号指标不裁切
- [ ] 手机：矮视口、软键盘弹出时输入框和提交入口可见
- [ ] 手机：固定栏避开刘海和底部手势条，滚动内容没被固定栏挡住
- [ ] 桌面：小窗口（如 1280×720）核心任务可用；宽屏空间先分给列，留白都有分组或阅读作用
- [ ] 空状态、加载中、错误状态都有内容，容器不塌；骨架屏与最终布局同形状

## 空间与形状

- [ ] 同类元素共享基线、尺寸和间距；每个区域和常驻控件说得出任务理由
- [ ] 没有卡片套卡片，没有只为沿用参考构图而加的区域
- [ ] 高密档没有通用卡片容器：区域贴边分区、1px 分隔线，卡片只留给独立对象和浮层
- [ ] 聚焦型任务（菜单、长表单、引导、结账、破坏性确认）保持标准尺寸；整页有让视线休息的留白
- [ ] 工具栏、表头、数据行高度同档；切密度时同一视图一起切
- [ ] 同类组件圆角一致；贴角嵌套表面曲线协调；共边组合没有圆角缝或重复边框
- [ ] 换方向、长标签、缩放、切密度后轮廓和分组仍清楚
- [ ] 数字列 `tabular-nums` 对齐，实时变化时不跳动

## 色彩

- [ ] 强调色面积 ≤10%，只出现在主操作、当前选择、关键数字
- [ ] 图表分类色与 UI 状态色没有混用
- [ ] 文字对比 ≥4.5:1（大字 ≥3:1）；识别控件或状态必需的图形线索与相邻色 ≥3:1
- [ ] 整页一个主题，局部区域不反色

## 内容与数据

- [ ] 长名称、ID、路径按 patterns.md 的换行 / 截断表处理；截断处用键盘也能看到全文
- [ ] 金额、计数不截断、不断行
- [ ] 实时计数有 `aria-live` 播报完整短语；可排序表头有 `aria-sort`
- [ ] 表单错误贴着字段并用 `aria-describedby` 关联；多个错误时有可聚焦的汇总
- [ ] 删除和批量操作能撤销，或确认文案写明对象和数量
- [ ] 图表有图例或直接标注，颜色之外还有区分手段，有表格或文字替代
- [ ] 数字、货币、日期用 `Intl` 按界面语言格式化
- [ ] 筛选、排序、搜索词、选中对象写进 URL：刷新、前进后退、分享链接后状态不丢
- [ ] 有未保存改动时离开前有提示，或已自动存草稿并能恢复

## 文案与去模板味

- [ ] 所有可见文案重读一遍：没有语病、指代不清和凑字数的说明句
- [ ] 示例数据像真实数据：没有 99.99%、123456、张三李四、Acme 这类占位；假数据明确标为示例
- [ ] 彩色圆点只表示真实状态，不当装饰
- [ ] 没有每个区块都加的小号大写眉标或 `01 / 02` 序号标签；`·` 分隔每行最多一个
- [ ] 同一操作全项目同名；只用一套图标库，不用 emoji 当图标
- [ ] 每个视图最多一个高亮主按钮
- [ ] 没有用负字距挤空间

## 性能

- [ ] 动画只动 `transform` / `opacity`；缓动取 `--dc-ease-*`；长列表不做逐项入场动画
- [ ] 图片、图表、异步内容预留尺寸，加载后不跳动（CLS < 0.1）
- [ ] 长列表的分页理由来自任务，虚拟化或 `content-visibility` 的理由来自实测渲染成本（见 tables.md 的「数据量与分页」）
- [ ] 滚动、缩放、输入等高频事件做节流或防抖
- [ ] 层级用 `--dc-z-*` 分档，没有随手写的 `z-index: 9999`

## 状态与可达性

- [ ] 持久选择、键盘焦点、悬停、按压、进行中、异常各自可辨
- [ ] `:focus-visible` 清楚且不引起布局位移；焦点环没被父容器 `overflow` 裁掉，也没被粘性元素遮住
- [ ] 输入有标签或可访问名称，占位符只作提示；图标按钮有可访问名称
- [ ] 核心任务能用键盘完成；滚动区有键盘进出路径
- [ ] 触屏常用操作实际热区约 44×44px（WCAG 2.2 AA 最低 24×24px 或适用例外），热区参与布局、互不重叠；圆角外框尺寸本身不能证明达标
- [ ] 拖拽、调比例等操作有按钮或键盘等效入口；指针移动约 4px 后才开始拖拽，`Esc` 能取消
- [ ] 快捷键写在提示或菜单里，不占用浏览器和系统常用快捷键，单字母快捷键在输入框里不生效
- [ ] 下拉、复选框、单选用原生元素，或自定义后补齐角色、状态和键盘操作
- [ ] 动效 80–180ms 只传达状态；`prefers-reduced-motion` 下关闭
- [ ] 反馈对应真实执行状态，不提前显示成功；点击后 100ms 内有可见反馈，超过约 1 秒有进度，失败给重试且保留输入
- [ ] 路由或主视图切换后焦点落到新内容；有「跳到主内容」链接；toast 不抢焦点

## 评价方式

在相同内容和视口下比较：有效可见信息、辨识速度、操作距离、上下文保持。总元素数量不能单独证明设计更好。

重复对象视图（列表、表格、树）在目标视口里实测并写出数字：折叠态行高、一屏可辨认的项数、不用展开就能直接操作的项数、内容区占视口宽度的比例；改版时和改版前同内容对比。这几项要在真实浏览器里截图或量取才算「预览验证」，只看 CSS 数值或假 DOM 测试算「静态检查」。密度是否提高以这几项数字为准。

评审时问题按影响排序：可达性 > 触控与交互 > 性能 > 布局与响应式 > 字体与色彩 > 动效与装饰。每条写位置（`文件:行号` 或界面区域）、问题和改法。
